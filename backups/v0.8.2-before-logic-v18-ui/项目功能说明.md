# 多平台 AI 同步输入器——项目功能说明（V1.0）

## 1. 项目定位

一款面向 Windows 的桌面程序。用户只需在一个窗口中输入问题或指令，程序便可将同一内容自动发送到多个已启用、已登录的 AI 平台，并集中显示各平台的执行进度、回复状态、耗时和结果摘要。

项目的核心价值是减少在多个网页之间重复复制、粘贴、提交和等待的操作，让多模型对比更快、更直观。

## 2. 首版目标

- 一次输入，同时发送到多个 AI 平台。
- 平台可自由勾选、排序、暂停和单独重试。
- 实时跟踪每个平台从准备到完成的全过程。
- 在一个界面中查看回复摘要，并可跳转到对应平台查看完整内容。
- 遇到登录失效、验证码、限流或页面结构变化时，准确提示并允许人工接管。
- 所有平台适配模块彼此隔离，便于后续增加或修复单个平台。

## 3. 目标用户与使用场景

### 目标用户

- 经常对比多个 AI 回答的个人用户。
- 需要多模型校验文案、翻译、代码或研究结论的团队。
- 希望减少重复操作、保留提问记录和结果状态的重度 AI 用户。

### 典型流程

1. 用户打开程序，程序检查各平台登录状态。
2. 用户选择本次启动 AI 平台所用的浏览器：Edge、Chrome、夸克或 360 浏览器，默认选择第一个已检测到的浏览器。
3. 用户勾选本次需要使用的平台。
4. 用户点击“一键拉起已选平台”，程序通过选中的同一个浏览器打开全部已选 AI 页面。
5. 用户输入问题，可附加图片或文件（平台支持时）。
6. 用户点击“发送到已选平台”。
7. 程序复用已经打开的各平台页面，自动填入并提交内容。
8. 主界面分别显示各平台的状态、耗时和回复预览。
9. 用户可复制单个平台结果、打开原会话、重新生成或再次发送。

## 4. 界面结构

### 4.1 左侧：平台与会话

- 浏览器选择位于 AI 平台列表之前，以 2×2 形式提供 Edge、Chrome、夸克、360 浏览器四个选项。
- 浏览器默认按标准安装目录自动检测；用户可为 Edge、Chrome、夸克、360 浏览器分别保存自定义 `.exe` 路径，并可一键恢复默认检测路径。
- 当前浏览器运行中修改路径时，程序会关闭旧控制会话并通过新路径重新拉起全部已选平台。
- 本次发送的所有平台统一使用当前选择的浏览器。
- 运行途中允许切换浏览器；切换会停止当前任务，并在新浏览器中重新打开全部已选平台。
- 为避免重复提问，切换后不会自动再次提交原内容，需要用户确认后重新发送。
- 提供“一键拉起已选平台”，只打开所有已选 AI 页面并显示“已打开”，不会自动发送输入内容。
- 平台列表：名称、图标、启用开关、登录状态。
- 拉起平台后自动识别逐平台登录状态：已登录、访客可用、未登录、需验证、可用但登录状态未知、不可用或检测失败。
- 平台排序：拖动调整执行顺序。
- 会话模式：新建会话、继续当前会话。
- 快捷操作：刷新登录状态、打开平台、平台设置。

### 4.2 中间：统一输入区

- 多行文本输入框。
- 当前字符数与平台限制提示。
- 文件、图片附件入口：支持多选、显示文件名和大小、单独移除，并在发送时上传到各个已选 AI。
- 各平台 AI 模式入口：拉起页面后读取当前账号实际可见的模式选项；登录、未登录或账号权限不同时，模式列表随检测结果变化。
- 默认“保持当前模式”，不再向用户展示页面上未检测到的静态模式。
- 常用提示词模板。
- “发送到已选平台”主按钮。
- Enter/Ctrl+Enter 发送方式设置。
- 定时发送和顺序/并行发送可作为后续能力。

### 4.3 右侧：运行状态与结果

每个平台显示一张独立状态卡片：

- 平台名称与当前状态。
- 状态进度：排队中 → 输入中 → 已提交 → 生成中 → 已完成。
- 本次耗时、开始时间、结束时间。
- 回复内容预览。
- 复制结果、打开原会话、停止、重试按钮。
- 错误详情和建议处理方式。
- 右侧状态区域从窗口顶部开始，占用原右上控制区释放的空间，以显示更长的回复预览。
- 默认 1–7 个平台时，各卡片按平台数量自动等分并填满整个右侧区域；添加更多平台导致卡片低于最小可读高度时才启用滚动。
- 状态统计集中显示在“实时状态”标题右侧；右下角显示与个人网页一致的“Design by Logic”签名。
- 左下任务、历史、设置和数据目录控制栏固定下沉，与中间拉起、发送按钮形成同一底部操作带。

## 5. 核心功能

### 5.1 多平台管理

- 添加、启用、停用和排序平台。
- 用户可在界面中手动添加其他 AI 平台，只需填写平台名称和完整聊天页面网址；自定义平台会本地保存并可删除。
- 自定义平台先使用通用输入框、发送按钮、停止按钮和回复区域识别规则；需要高稳定性时再升级为平台专用适配器。
- 保存每个平台的浏览器配置和登录状态。
- Edge、Chrome、夸克、360 浏览器使用相互独立的持久化登录资料，切换时不混用会话数据。
- 每个浏览器首次受控启动时，从该浏览器最近使用的个人资料中一次性导入登录会话到程序专用资料；后续登录状态在专用资料中持续保存。
- 不直接控制浏览器正在使用的原始个人资料，以避免资料锁冲突和原始资料损坏。
- 平台连通性检测。
- 平台适配版本提示，页面变化时可停用异常适配器。

### 5.2 同步输入与提交

- 同一文本并行发送到多个平台。
- 发送前检查输入框、发送按钮和登录状态。
- 可为单个平台追加前置提示词或调整内容。
- 防止重复点击造成重复提交。
- 支持全局停止和单平台停止。

### 5.3 输出状态跟踪

统一状态定义：

| 状态 | 含义 |
|---|---|
| 未开始 | 本轮尚未执行 |
| 排队中 | 等待可用执行槽位 |
| 正在输入 | 已定位输入框并写入内容 |
| 已提交 | 已触发平台发送动作 |
| 生成中 | 平台正在持续输出 |
| 已完成 | 检测到生成结束，可读取结果 |
| 需人工处理 | 登录、验证码、授权弹窗等需要用户操作 |
| 失败 | 超时、页面变化、网络错误或元素未找到 |
| 已取消 | 用户主动停止 |

完成判定应组合使用：停止按钮消失、发送按钮恢复、输出内容在一段时间内不再变化、平台特有完成标识。不得只依赖固定等待时间。

### 5.4 结果查看与导出

- 回复预览与一键复制。
- 打开平台原始会话查看完整回复。
- 按任务保存问题、平台、时间、耗时、状态和结果。
- 导出 Markdown、TXT、JSON；后续可增加 Word/Excel。
- 支持按平台并排对比回复。

### 5.5 异常与人工接管

- 登录失效：打开对应窗口并提示重新登录。
- 验证码或人机验证：暂停该平台，等待用户完成后继续。
- 限流：显示平台提示并支持延迟重试。
- 页面结构变化：保留截图和错误信息，避免静默失败。
- 网络中断：有限次数重试，防止重复提交。
- 平台不可用不影响其他平台继续执行。

## 6. 设置项

- 默认启用平台。
- 最大并行数量。
- 单平台超时时间和重试次数。
- 浏览器窗口默认隐藏或显示。
- 是否保存完整回复。
- 历史记录保留天数与一键清理。
- 下载和导出目录。
- 开机启动、最小化到托盘和完成通知。

## 7. 建议支持的平台阶段

### 第一阶段

首版默认包含以下 7 个网页平台，并复用程序专用浏览器中的用户登录状态：

- Claude
- ChatGPT
- Grok
- Google Gemini
- DeepSeek
- 豆包
- 千问（阿里 AI 助手）

所有平台默认启用，用户可在每次发送前单独关闭。平台适配器彼此独立，单个平台页面变化或执行失败不会阻断其他平台。

### 第二阶段

- 增加更多国内外 AI 平台。
- 允许同一平台配置多个账号或多个模型。
- 增加 API 模式，与网页自动化模式并存。
- 提供提示词变量和批量任务。

## 8. 技术实现建议

- 桌面界面：优先考虑 Tauri + React，体积较小；也可使用 Electron 以提高开发速度。
- 网页控制：使用 Playwright 管理独立、持久化的浏览器会话。
- 平台适配：每个平台一个适配器，实现登录检查、输入、提交、状态检测和结果提取。
- 状态中心：采用统一任务状态机，平台事件实时推送到桌面界面。
- 本地存储：SQLite 保存设置、任务历史和错误日志。
- 敏感信息：不保存用户密码；复用浏览器登录状态，并加密保存必要的本地会话数据。

## 9. 合规与边界

- 不绕过验证码、人机验证、登录保护或平台安全机制。
- 用户应遵守各 AI 平台服务条款、账号限制和内容规则。
- 默认只在用户本机处理输入与结果，不将内容上传到额外服务器。
- 提供隐私模式：任务结束后不保存问题和回复。
- 页面自动化可能随平台更新失效，因此需要可更新的独立平台适配模块。

## 10. 首版验收标准

- 至少 3 个平台可完成登录状态识别、自动输入和提交。
- 单次任务可同时选择多个平台，且单个平台失败不会阻断其他平台。
- 每个平台都能正确显示输入中、生成中、完成、需人工处理和失败状态。
- 完成后可查看结果预览、复制结果并打开原会话。
- 历史记录可检索，且可关闭保存。
- 登录失效、验证码、网络中断和页面元素变化均有明确提示。
- 连续执行 20 轮测试，无重复提交、任务串线或程序崩溃。
