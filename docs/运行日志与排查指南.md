# 运行日志与排查指南

## 日志位置与格式

- 默认目录：`%LOCALAPPDATA%\MultiAIInput\logs`
- 主文件：`runtime.jsonl`，每行一个 JSON 事件。
- 单文件上限 5 MB，最多保留 5 个轮转备份；启动时清理超过 14 天的备份。
- 默认级别为 `INFO`。排查细节时，可在启动前设置环境变量 `MULTIAI_LOG_LEVEL=DEBUG`。
- 若默认目录不可写，程序降级到 `%TEMP%\MultiAIInput\logs`；日志写入过程中再次失败时，`WARN/ERROR` 会写入 `%TEMP%\MultiAIInput\runtime-emergency.jsonl` 或标准错误输出。日志故障不会终止主功能。

每条日志至少包含 `timestamp`（本地时区）、`level`、`module`、`event`、`session_id` 和 `message`。异步操作按需带有 `operation_id`、`task_id`、`object_id`、`result`、`duration_ms`、`error_code` 等字段。

日志不记录提示词、AI 完整回复、Cookie、令牌、授权头或附件内容。路径只保留文件名、位置类别和不可逆短哈希；URL 删除查询参数和片段。诊断包中的状态摘要也不包含历史正文和回复正文。

## 级别规则

- `INFO`：启动和退出、用户操作被接收、操作终态、经验证的数据写入、重要状态变化。
- `WARN`：可以继续运行的异常、降级、超时后页面仍可用、重试过程、日志目录降级。
- `ERROR`：操作最终失败、未处理异常、后台任务异常、资源释放失败。
- `DEBUG`：数据写入开始、附件不存在等仅在深入排查时需要的过程。

轮询异常按“平台 + 异常类型”在 60 秒窗口内限频；下一条会带上被抑制次数。任务终态和关键错误不参与静默过滤。异步日志队列容量为 5000；队列满时低级日志可丢弃并在退出摘要中报告数量，`WARN/ERROR` 直接同步写入备用处理器。

## 导出诊断日志

打开“设置”，点击“导出诊断日志”。程序会在 `%LOCALAPPDATA%\MultiAIInput\diagnostics` 生成 ZIP 并打开目录。ZIP 包含轮转日志、脱敏环境信息和状态摘要。

## 简短排查步骤

1. 根据用户报告时间，在 `runtime.jsonl*` 中找到最接近的 `timestamp`，确定 `session_id`。
2. 找到对应的 `user_action.received`，复制其 `operation_id`，搜索全部同 ID 事件。
3. 同步发送操作再按 `task_id` 搜索，可串起任务创建、各平台状态变化、首次失败、重试及最终结果。
4. 先看 `*.finished` 的 `result`：`success`、`failure`、`cancelled`、`timeout` 或 `degraded`。不要把 `attempt_failed` 或 `retry_started` 当成最终失败。
5. 错误事件查看 `error_type`、`error_code`、`exception_chain` 和 `stack_trace`；再看同一 ID 前后的外部调用、数据读写及状态变化。
6. 若出现 `lifecycle.previous_session_incomplete`，说明上次进程未正常退出；`pending_operation_ids` 是中断时仍未完成的操作。突然断电或强制结束时，异步队列中尚未落盘的低级日志可能丢失，最后数条事件不保证完整。
7. 若只能看到“外部页面结构未识别”而没有平台响应细节，日志只能定位到选择器/导航阶段，不能单独证明账号权限、服务端内部原因或网页内容本身；此时需要用户在原平台页面核对提示。
