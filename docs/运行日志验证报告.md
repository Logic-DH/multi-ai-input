## 验证结果

| 场景 | 方式 | 结果与可定位证据 |
| --- | --- | --- |
| 正常启动、HTTP 请求、诊断导出、正常退出 | 启动本地服务，读取状态，调用诊断导出和退出接口 | `application.startup.verified`、同一 `operation_id` 的 `user_action.received` 与 `diagnostics.export.finished`、`application.shutdown.completed` 均存在；进程退出码 0 |
| 启动初始化失败 | 预占本地端口后启动服务 | `application.startup.failed` 记录 `PermissionError`、WinError 10013、完整脱敏栈；会话终态为 `failure`，进程退出码 1 |
| 数据文件不存在 | 读取隔离目录中的缺失 JSON | 记录 `data.read.defaulted`，结果为 `defaulted`，未误报失败 |
| 数据文件损坏 | 读取内容为 `{broken` 的 JSON | 记录 `data.read.failed`、`JSONDecodeError` 和栈，结果为 `degraded`，程序返回默认值继续运行 |

| 后台任务异常 | 在真实自动化事件循环提交抛错协程 | `background.task.failed` 与 `validation.background.finished(result=failure)` 共享操作/任务标识 |
| 浏览器依赖缺失 | 使用没有 Playwright 的解释器执行真实浏览器初始化路径 | `ModuleNotFoundError`、失败位置和 `validation.browser_launch.finished(result=failure)` 完整可见 |
| 本机浏览器子进程 | 对检测到的浏览器执行 Playwright 无头启动和页面读写 | Edge、Chrome、夸克通过；360 未安装并明确报告 `NOT_INSTALLED`，未伪造成功 |
| 后台取消、超时、重试后成功 | 结构化日志隔离场景模拟终态和重试序列 | 首次 `attempt_failed(result=retrying)`、`retry_started` 和最终 `finished(result=success,retry_count=1)` 可区分 |

## 未安全复现的边界

- 未主动填满磁盘，也未修改真实目录 ACL；这两种操作可能影响用户系统。已通过不可写目录和处理器备用路径验证降级逻辑。
- 未强制结束正在写日志的真实进程或模拟断电。通过残留会话标记验证了下次启动识别；突然终止时，队列中尚未写入的低级日志仍可能丢失。
- 未向真实 AI 平台发送测试内容，也未伪造账号登录、平台服务端 5xx 或真实网络断线。网络超时/重试日志链通过隔离异常注入验证；账号权限和平台服务端内部原因仍需结合网页提示判断。
- 未安装的 360 浏览器仅报告缺失，未验证其真实进程启动。

日志可以判断故障发生在本地请求、数据、浏览器启动、页面导航、状态检测或发送阶段，但不能仅凭本地日志推断第三方平台内部故障、账号封禁原因或网页未暴露的服务端状态。
